The Influence of SRS Components on AI-Generated Code Quality

We investigate how different parts of a software requirements specification (SRS) influence the functional correctness and structural quality of code produced by an AI coding agent.

This study is ongoing. The findings below are preliminary and come from our pilot experiment. I’ll share the final findings and a link to the report here once the project is complete.

Research questions

  1. RQ1. Which SRS components have the greatest influence on the quality of AI-generated code?
  2. RQ2. How does the omission of specific SRS components influence functional correctness and structural quality in AI-generated code?

Pilot methodology

We compared six versions of the specification for the same to-do list application. The complete specification served as the baseline. Four variants each omitted one section, and a sixth contained only functional requirements. We kept the coding agent’s configuration fixed and ran it five times per variant, producing 30 implementations.

We evaluated functional correctness using a shared suite of 39 JUnit tests and used SonarQube to collect static code metrics. Repeating each generation let us examine how much the implementations varied even when the specification stayed the same.

Preliminary findings

Implementations that passed every test retained in the analysis:

Complete specification
5 out of 5
Functional requirements only
0 out of 5

In the variant that omitted non-functional requirements, the generated code was shorter and had less documentation than the baseline. Omitting data requirements coincided with fewer issues reported by SonarQube and fewer explicit error checks. We therefore interpreted the issue counts alongside what we observed in the code.

Limitations

The pilot used one application and five runs per specification, so smaller effects may have gone undetected. Some requirements also appeared in more than one section, meaning that information could still be present after we removed a section. The test results cover the behaviours exercised by the shared test suite.
